# 사내판 / 사외판 분리 설계

---

## 1. 결론부터

**저장소를 나누지 않는다. 코어 하나에 프로파일 둘.**

```
harness/        ← 코어. 네트워크 전제 없음, 프로바이더 전제 없음
profiles/
  enterprise.json   ← 사내: 망분리, 로컬 추론, 승인 게이트
  personal.json     ← 사외: 클라우드 프로바이더, 개인 볼트
vault/
  work/             ← 사내 데이터. 절대 교차하지 않음
  personal/         ← 개인 데이터
```

### 저장소를 나누면 안 되는 이유

나누고 싶은 유혹이 크다. 실제로 나누면 이렇게 된다.

1. 두 저장소가 3개월이면 갈라진다. 개인판에서 고친 버그가 사내판에 안 온다.
2. 사내판은 실사용이 적어 GEPA 태스크뱅크가 안 쌓인다. 개선 루프가 굶는다.
3. 보안 검토를 두 번 받아야 한다.

### 그런데 안 나누면 위험한 이유

같은 코드베이스에서 개인 프로파일이 사내 데이터를 만질 수 있다.
**이것이 실제 유출 경로다.** 아키텍처 다이어그램이 아니라 "사내 PC에서
개인 설정으로 띄우고 s2p 파일을 Claude에 붙여넣는 것"이 진짜 사고다.

### 그래서: 코어는 공유, 경계는 코드로 강제

```python
# harness/policy/engine.py
def validate(self):
    if self.edition == "enterprise":
        if self.egress_default != "deny":
            raise PolicyError("enterprise 프로파일의 egress_default는 deny 여야 한다")
        if not self.capture_require_screening:
            raise PolicyError("enterprise 프로파일은 캡처 스크리닝을 끌 수 없다")
        cloud = [n for n, p in self.providers.items() if p.get("transport") == "cloud"]
        if cloud:
            raise PolicyError(f"enterprise 프로파일에 클라우드 프로바이더 금지: {cloud}")
```

사내 프로파일을 느슨하게 고치면 **로드 자체가 실패한다.** 주석이 아니라 예외다.
그리고 게이트 G-02가 매 CI에서 이 불변식을 확인한다.

## 2. 프로파일 고정 (pinning)

가장 중요한 한 줄이다.

```json
"pinned_to": ["*.corp.local", "EMC-WS-*"]
```

사내 프로파일은 사내 호스트에서만 로드된다. 반대로 개인 프로파일에는 사내
도메인이 `egress_deny`에 들어간다.

```python
PolicyEngine(enterprise_profile, hostname="my-home-laptop")
# → PolicyError: 프로파일은 ['*.corp.local', 'EMC-WS-*'] 에만 고정돼 있다
```

세션마다 프로파일을 갈아끼우는 UI는 **만들지 않는다.** 전환이 쉬우면 실수로
전환된다. 프로파일은 설치 시점에 결정되고 그 뒤로 바뀌지 않는다.

## 3. 표면별 대조

| 표면 | enterprise | personal |
|---|---|---|
| `egress` 기본값 | `deny` | `confirm` |
| 프로바이더 | 로컬 vLLM만 (`transport: local`) | Claude / GPT / Gemini CLI + 로컬 |
| `exec` 기본값 | `confirm` | `confirm` |
| 화면 캡처 | 앱 허용목록 **필수** + 스크리닝 필수 | 차단목록 + 스크리닝 필수 |
| 볼트 | `vault/work` | `vault/personal` |
| 보존기간 | 180일 | 무기한 |
| 일정 생성 | 사용자 승인 | 사용자 승인 |
| 일정 삭제 | **관리자 승인** | 사용자 승인 |
| 볼트 반출 | **보안팀 승인** | 사용자 승인 |
| 호스트 고정 | 있음 | 없음 |

`exec` 기본값이 양쪽 다 `confirm`인 것은 의도적이다. 개인 PC라고 AI가 만든
PowerShell을 무단 실행할 이유는 없다.

## 4. 개인판이 사내판을 먹여 살린다

이 구조의 실질적 이득이다.

```
개인판 (매일 사용)
   │  실사용 발화, 실패 사례, 재지시 패턴이 쌓인다
   ▼
태스크뱅크 후보  ──[비식별화 게이트]──►  사내판 태스크뱅크
   │                                        │
   ▼                                        ▼
GEPA 루프 (클라우드 프로포저 사용 가능)   GEPA 루프 (로컬 프로포저)
   │                                        │
   ▼                                        ▼
개선된 아티팩트  ────[검토 후 이식]────►  사내 아티팩트
```

사내판은 실사용량이 적어 태스크뱅크가 잘 안 쌓인다. 개인판은 매일 쓰이므로
잘 쌓인다. **개선의 원동력이 개인판에서 나온다.**

### 비식별화 게이트 — 넘어가도 되는 것과 안 되는 것

| 넘어간다 | 넘어가지 않는다 |
|---|---|
| 발화의 **문형** ("~하는 코드 짜줘") | 발화 원문 |
| 분류 라벨 | 프로젝트명, 부품명, 파일 경로 |
| 실패 유형 (오분류/저마진) | 수치, 측정값, s2p 데이터 |
| 개선된 **규칙 패턴** | 화면 캡처 일체 |

방향은 **개인 → 사내 단방향**이다. 사내 데이터는 어떤 형태로도 개인 볼트로
넘어가지 않는다.

> 이 게이트는 아직 구현되지 않았다. Phase 2 항목이며, 그때까지는 태스크뱅크
> 항목을 **손으로 작성**한다. 자동 이관을 검증 없이 켜면 이 문서 전체가 무의미해진다.

## 5. 사외판을 개인용으로 쓸 때

사내 요구와 무관하게 개인 생산성 도구로 성립해야 한다. 사내판에서 빼는 것과
개인판에만 넣는 것.

**빼는 것**

- 승인 워크플로 (혼자 쓰는데 승인자가 없다)
- 보존기간 강제
- 호스트 고정
- EMC 전용 카테고리는 남기되 비활성화 가능하게

**개인판에만 넣는 것**

| 기능 | 설명 |
|---|---|
| 클라우드 프로바이더 라우팅 | 작업 유형별로 Claude/GPT/Gemini 자동 선택 |
| 개인 일정 연동 | 로컬 `.ics` 우선. 캘린더 API는 선택 |
| 크로스 디바이스 볼트 | 개인 Git 저장소 동기화 |
| 가계·건강 등 개인 카테고리 | 라우터 아티팩트에 카테고리만 추가하면 된다 |

**두 판이 공유하는 것** — 여기가 이 설계의 핵심 자산이다.

- 이벤트 원장 스키마와 해시 체인
- 아이디어 메모북 상태 기계
- GEPA 루프 전체
- 샌드박스 정책
- 정책 엔진 (설정만 다름)

## 6. 배포

| | enterprise | personal |
|---|---|---|
| 설치 | 사내 이미지 레지스트리, 오프라인 설치 스크립트 | `git clone` + `python3` |
| 모델 | 사내 GPU 노드 vLLM | 로컬 Ollama 또는 클라우드 API |
| 업데이트 | 보안 검토 후 사내 미러 | 직접 pull |
| 원격 배포 | 망연계 CI/CD 프록시 경유 (§14.2) | 직접 |

코어가 Python 3.11 표준 라이브러리만 쓰므로 사내 설치는 **파일 복사로 끝난다.**
이 제약을 깨지 않는 것이 사내 도입 난이도를 결정한다 — Ainative가 같은 제약을
지키는 이유와 같다.

## 7. 시험

에디션 분리는 문서가 아니라 시험으로 유지된다.

| 시험 | 확인하는 것 |
|---|---|
| `test_enterprise_rejects_cloud_provider` | 사내 프로파일에 클라우드 넣으면 로드 실패 |
| `test_enterprise_cannot_open_egress` | `egress_default`를 열면 로드 실패 |
| `test_enterprise_denies_external_hosts` | 외부 도메인 차단 |
| `test_profile_pinning_blocks_wrong_host` | 사내 프로파일이 외부 호스트에서 안 뜬다 |
| G-07 볼트 경로 분리 | 두 볼트가 겹치거나 중첩되지 않는다 |
| G-02 프로파일 불변식 | 위 전부를 CI에서 재확인 |
